# MECHEN H1-Pro kernel build harness

Builds Linux 3.18.119 for the MT6750 (`k50v1_64_bsp`) and packages it as a `boot.img` in the stock layout.

## Layout

| Path | What |
|---|---|
| `kernel-src.sparseimage` | Case-sensitive APFS volume (the kernel tree breaks on case-insensitive macOS FS). Mounted at `src/` automatically by `build.sh`. |
| `src/linux` | Kernel source: [zhiluan233/android_kernel_cyberfurryrobot_cfb001](https://github.com/zhiluan233/android_kernel_cyberfurryrobot_cfb001) @ `a30c78c0f612b29a30f4aeb6e89a39b80b0ea3c3` (3.18.119, MT6755, has `k50v1_64_bsp` board files). Unverified third-party upload: review before trusting. |
| `src/obj` | Out-of-tree build objects (on the case-sensitive volume) |
| `harness/Dockerfile` | Ubuntu 18.04 x86_64 + AOSP `aarch64-linux-android-4.9` (same GCC 4.9 family as stock) |
| `harness/build-in-container.sh` | config → build → package, with safety checks |
| `harness/mkbootimg.py` | Repacker: header v1 cloned from stock, new kernel blob, re-signed VB1.0 boot signature |
| `harness/keys/` | AOSP **public** verity test key. The stock boot.img is signed with this key, so the signature provides no security. |
| `harness/config.fragment` | (optional) extra `CONFIG_…` lines appended to the stock config |
| `out/` | `boot-<stamp>.img` + `.sha256`, `.config`, `.version`, `config-lost.txt`, `build.log` |

## Use

```sh
./build.sh selftest   # repack stock boot.img → must be BYTE-IDENTICAL (verified 2026-11-18)
./build.sh            # full build → out/boot-<stamp>.img
./build.sh shell      # debug shell inside the build container
DTB_MODE=built ./build.sh   # use the tree's own DTB instead of the stock one (default: stock)
```

Starts colima with Rosetta (`--vm-type vz --vz-rosetta`) if Docker isn't running.

## Safety rules

- The config is the **exact stock config** (IKCONFIG). Options the tree can't satisfy are listed in `out/config-lost.txt`.
- If board drivers are missing (LCM `st7701boe`/`nv3049f`, Hynitron touch `CTSXXXX`, exFAT), the image is named `…-UNSAFE-missing-board-drivers.img`. **Never flash those**: no display, no touch.
- The stock DTB is appended by default, so the board description is identical to stock.
- Flash only after the M2 backup and the M3 signature test (see `../FIRMWARE_REVERSE_ENGINEERING.md`). Prefer `fastboot boot out/boot-….img` (RAM boot, nothing written) if LK supports it.

## Known gaps (from M7)

Not in the source tree and must be ported before a flashable image exists: `st7701boe` + `nv3049f` LCM drivers, Hynitron CST3XX v1.2 touch, the next/prev/contacts key EINT drivers, `xunhubattery`, MSA311 accelerometer, exFAT.

## Build status (2026-11-18, evening)

`./build.sh` produces a complete, signed `boot.img` (still named `UNSAFE` until touch is ported). Kernel release string `3.18.119` matches stock.

**Done (patches 0001–0010):** tree repairs (case-collision losses, committed artifacts, warnings); panel drivers `st7701boe` + `nv3049f` regenerated byte-exact from stock (`tools/gen_lcm.py`); stock single-profile battery tables (`tools/gen_battery.py`); flashlight/charger fixed to the stock linear-charger design; **vendor-module ABI**: all 6 stock vendor modules (wmt_drv, wlan_drv_gen2, bt_drv, fmradio_drv, gps_drv, wmt_chrdev_wifi) pass the modversions check (`harness/check_modversions.py`, runs on every build → `out/modversions.txt`). Fixes: `rtc_time.tm_cnt` with 36-byte ioctl numbers (exact stock CRC), 2-member `wmt_platform_bridge`; two CRCs pinned where the ABI was verified identical against stock code (`__dynamic_pr_debug`, `wmt_export_platform_bridge_register`).

**Update (patches 0011–0013):** exFAT 1.2.9 (`exfat-nofuse` 01c30ad5, the exact stock version), the side music keys (prev/next/contacts EINT, stock keycodes 100/108/103 and DT nodes), and a clean-room Hynitron CST3XX touch driver reproducing the stock protocol (I2C 0x5a, reg 0xD0xx, type-A MT, 3 touch keys). The touch driver has **no touch-IC firmware update path at all**. `./build.sh` now produces `out/boot-<stamp>.img` without the UNSAFE tag.

"Not UNSAFE" only means no known-missing critical driver. **Nothing has run on hardware yet.** First boot must be `fastboot boot` (RAM only) after the M2 backup and the M3 signature test.

Note: occasional `Error 132` (SIGILL in cc1 under Rosetta) is an emulation flake. Just re-run.
